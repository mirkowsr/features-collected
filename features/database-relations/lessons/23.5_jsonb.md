# Lesson 23.5 — JSONB: semi-structured data inside a relational database

**Goal:** Know when a JSONB column beats a normalized table, and how to query and index JSON.

---

## Theory

Postgres lets a column hold JSON. That sounds like heresy after lesson 04 (normalization) — and usually it is. But used deliberately, `JSONB` is one of Postgres's best features.

### JSON vs JSONB

| | `JSON` | `JSONB` |
|---|--------|---------|
| Storage | raw text, exactly as inserted | parsed binary |
| Key order / whitespace | preserved | discarded |
| Duplicate keys | kept | last one wins |
| Indexable | no | **yes (GIN)** |
| Verdict | logs you never query | ✅ default choice |

### When to use JSONB

✅ **Good fits:** per-row variable shape (product attributes: a bike has wheel size, a shirt has size chart), third-party payloads you store verbatim, feature flags/settings, audit diffs.

❌ **Bad fits:** anything you filter/join/aggregate on regularly, anything with a stable shape (that's a column), relationships (that's a table — FKs can't point into JSON).

> Rule of thumb: if the *database* needs to understand the data, make it a column. If only the *application* does, JSONB is fine.

### Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `->` | get field/element as JSON | `attrs -> 'color'` |
| `->>` | get field/element as **text** | `attrs ->> 'color'` |
| `#>>` | nested path as text | `attrs #>> '{dims,width}'` |
| `@>` | contains (left ⊇ right) | `attrs @> '{"color":"red"}'` |
| `?` | key exists | `attrs ? 'color'` |
| `jsonb_each` | expand to key/value rows | `SELECT * FROM jsonb_each(attrs)` |

`->>` returns text, so comparing numbers needs a cast: `(attrs->>'weight')::numeric > 5`. A failed cast on one bad row kills the whole query — another reason stable data belongs in columns.

### Indexing JSONB

A **GIN** index (lesson 23's type table) accelerates `@>`, `?` and friends:

```sql
CREATE INDEX idx_products_attrs ON sales.products USING GIN (attributes);
```

Rows where the key *exists* can also get a plain B-tree expression index on `(attributes ->> 'color')` — smaller, but only helps equality on that one key.

## Worked example — product attributes

```sql
ALTER TABLE sales.products ADD COLUMN attributes JSONB;

UPDATE sales.products
SET attributes = '{"color": "red", "sizes": ["S","M","L"], "dims": {"width": 30}}'
WHERE productid = 100;

-- text extraction (note the quotes in -> vs none in ->>)
SELECT product, attributes->>'color' AS color, attributes->'sizes' AS sizes_json
FROM sales.products;

-- containment: red products that stock size M
SELECT product FROM sales.products
WHERE attributes @> '{"color": "red", "sizes": ["M"]}';
```

## Exercises

1. Add an `attributes JSONB` column to `sales.products` and fill two rows with different shapes (a bike: `{"wheel_size": 28}`, a shirt: `{"size_chart": "EU"}`). Query both with one `SELECT product, attributes->>'...'` per shape — what do the mismatched rows return for the other's key?

2. Write the containment query for "all products whose `sizes` array includes `XL`". Then try expressing it with `->>` instead of `@>` — why does that fail?

3. Create the GIN index above on `bigsalesdb` (generate attributes there first, or test on the small table and just read the plan). Run `EXPLAIN` on your exercise-2 query before and after. Which scan appears?

4. Insert a row with `attributes = '{"stock": "not-a-number"}'`, then run `SELECT avg((attributes->>'stock')::int) FROM sales.products`. What happens, and how does `CASE WHEN (attributes->>'stock') ~ '^\d+$' THEN ... END` (lesson 14) defend it? What's the *real* lesson about numeric data in JSONB?

5. **Normalization audit:** a teammate proposes storing `{"customer_name": ..., "customer_country": ...}` inside `orders.attributes` "to avoid joins". Which anomalies from lesson 04 does this reintroduce? Write the query that now *can't* be enforced by any constraint.

6. **Predict before you run:** does `UNIQUE` on a JSONB column treat `{"a":1,"b":2}` and `{"b":2,"a":1}` as equal? Test both as `json` and `jsonb` — the answer reveals exactly what the binary format normalizes away.
