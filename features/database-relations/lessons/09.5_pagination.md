# Lesson 09.5 — Pagination: OFFSET vs keyset (cursor)

**Goal:** Return data page by page — and understand why `OFFSET` degrades while keyset pagination stays fast.

---

## Theory

Listing endpoints can't return a million rows. Both pagination styles exist to solve this, and they scale very differently.

### OFFSET pagination — the familiar one

```sql
SELECT orderid, orderdate, sales
FROM sales.orders
ORDER BY orderid
LIMIT 3 OFFSET 6;    -- page 3, page size 3
```

Page *n* = `LIMIT size OFFSET (n-1) * size`. Simple, and lets you jump to any page.

**The hidden cost:** to serve `OFFSET 100000`, Postgres must **read and discard 100,000 rows** first. Every page costs more than the previous one. Worse, if rows are inserted while the user pages, results shift — the same row appears twice or vanishes.

### Keyset (cursor) pagination — where you left off

Instead of skipping rows, remember the **last value seen** and continue after it:

```sql
-- first page (page size 3)
SELECT orderid, orderdate, sales
FROM sales.orders
ORDER BY orderid
LIMIT 3;

-- next page: orderid of the last row from page 1 was 3
SELECT orderid, orderdate, sales
FROM sales.orders
WHERE orderid > 3           -- the "cursor"
ORDER BY orderid
LIMIT 3;
```

Every page costs the same, index-backed (lesson 23) regardless of depth. No duplicates, no skips — concurrent inserts land *after* your cursor, not inside already-seen pages.

### Comparison

| | OFFSET | Keyset |
|---|--------|--------|
| Page 1 cost | tiny | tiny |
| Page 10,000 cost | scans 100k rows | same as page 1 ✅ |
| Jump to arbitrary page | ✅ | ❌ (forward/back only) |
| Stable under concurrent writes | ❌ rows shift | ✅ |
| "Total pages: 347" | needs a `COUNT(*)` | needs a `COUNT(*)` |

### Requirements & gotchas

- The cursor column must be **unique and ordered** — a PK is perfect.
- Sorting by a non-unique column (e.g. `orderdate`)? Add a tiebreaker: `ORDER BY orderdate, orderid` with cursor `WHERE (orderdate, orderid) > ('2025-03-01', 9010)` (a **row comparison**).
- Descending lists (newest first) flip the operator: `WHERE orderid < cursor`.

---

## Worked example — newest-first orders feed

```sql
-- page 1: the 3 most recent orders → (10, 2025-03-15), (9, 2025-03-10), (8, 2025-02-18)
SELECT orderid, orderdate, sales
FROM sales.orders
ORDER BY orderdate DESC, orderid DESC
LIMIT 3;

-- page 2: last row seen was (2025-02-18, 8) → returns orders 7, 6, 5
SELECT orderid, orderdate, sales
FROM sales.orders
WHERE (orderdate, orderid) < ('2025-02-18', 8)
ORDER BY orderdate DESC, orderid DESC
LIMIT 3;
```

The API returns the rows plus the cursor (`orderdate` + `orderid` of the last row); the client sends it back for the next page.

## Exercises

1. Paginate `sales.orders` with `LIMIT 3 OFFSET n` through all pages. Repeat with keyset pagination (`WHERE orderid > ?`). Verify both visit every order exactly once.

2. While paginating with OFFSET in one session, insert a new low-`orderid` row from a second session midway through. What do you observe? Repeat with keyset — what changes?

3. Write the keyset query for "customers by name" (`ORDER BY lastname, firstname`). `lastname` isn't unique — and `salesdb` even has a NULL `lastname` — what goes wrong when two customers tie (or NULL) on the cursor column, and how does the `(lastname, firstname, customerid)` row-comparison cursor fix it? (Bonus: how does `NULLS LAST` interact with the `>` cursor comparison?)

4. Run `EXPLAIN ANALYZE` on `LIMIT 10 OFFSET 0` vs `LIMIT 10 OFFSET 10000` against a generated large table (lesson 22.5). Compare `actual time`. Then run the keyset equivalent — which plan wins, and which node in the plan explains why?

5. Your product manager wants page numbers ("Page 12 of 347") *and* fast performance on 2M rows. Which pagination style do you pick, what's the compromise, and what does the `COUNT(*)` cost you? (Run `EXPLAIN ANALYZE SELECT count(*) ...` on the big table to quantify it.)

6. **API design:** an endpoint accepts `?cursor=`. What should happen on an empty result — and how does the client distinguish "end of list" from "page of zeros"? Design the response shape.
